# chapter-audit-checklist (章节自动审计清单 v1.0)

> **Role**: 质量网守，在每章定稿前生成一份个性化的审计清单，涵盖故事、约束、风格、追读力四维。
>
> **Philosophy**: 有清单的质检是科学的，无清单的质检是盲目的。

## 核心职责

1. **智能生成**: 基于该章的执行包、约束、类型等，自动生成审计清单
2. **四维审计**: 覆盖故事完整性、约束激活、风格规范、追读力设计
3. **可视化检查**: 输出格式便于逐项勾选
4. **风险评级**: 自动识别"若此项失败则整章报废"的关键项

## 输入

```json
{
  "chapter": 100,
  "project_root": "D:/novel/webnovel-writer",
  "execution_package": ".webnovel/chapter_packages/ch0100_execution_package.md",
  "fine_outline": "大纲/第0100章-细纲.md",
  "draft": "正文/第0100章.md",
  "constraint_config": ".webnovel/constraint_activation_calendar.md"
}
```

## 输出

### 输出 1: 四维审计清单 (Markdown)

```markdown
# 第 0100 章《XXXX》审计清单

**生成时间**: 2026-04-06
**章节类型**: 战斗+突破
**执行包符合度**: 75% (已在之前纠正)

## 一、故事完整性 (Story Integrity)

**本章核心目标**: 🎯 主角突破筑基期，反派首次显露獠牙

### 1.1 开场与承接 ✅ 关键项
- [ ] 开头是否接住了上章的钩子？ (上章: "砰——枪声响了")
  - 检查方式: 查看第 1 段，是否继续枪战或其后续
  - 若失败: 整章公信力崩溃，**必须修改**
  - 参考位置: 第 1-100 字

- [ ] 开局代入感是否足够快？ (目标: 前 200 字内进入冲突)
  - 检查方式: 第 200 字时，读者是否已知"发生了什么"
  - 若失败: 开球不好，需补充环境/动作线索
  - 典型问题: 过多环境描写导致"等等发生什么呢"

### 1.2 中段推进 ✅ 关键项
- [ ] 本章是否有"清晰的推进点"？ (选其一: 关系变化 / 信息获取 / 能力突破 / 冲突升级)
  - 检查方式: 能否用一句话总结本章的改变
  - 若失败: 本章"无推进"，是灌水章，**建议删除或合并前章**
  - 本章预期推进: 主角从"逃跑" → "放弃逃跑，主动迎战" 
    - 检查: 是否有明确的"心理转折点"? (应该在第 60% 进度处)

- [ ] 本章是否存在"至少一个高潮点"？ (可以是战斗高潮、情感高潮或认知高潮)
  - 检查方式: 查找最紧张/最激烈/最感人的段落
  - 若失败（无高潮）: 本章平铺直叙，需补充冲突激化

- [ ] 中段是否有"局面变化"？ (被动 → 主动 / 弱势 → 暂时领先 / 无知 → 意识到)
  - 检查方式: 第 40%-60% 进度，局面是否不同于开场
  - 本章例子: 反派突然加速，主角无处可逃 → 主角决定拼死一搏

### 1.3 结尾与钩子 ✅ 关键项
- [ ] 本章结尾是否设置了追读力钩子？ (计划钩子类型: 危机钩 + 强度标准: 🔴 强)
  - 检查方式: 最后 150 字是否营造出"必须看下一章"的冲动
  - 钩子强度评估:
    - 🟢 弱: 读者"好像还行"
    - 🟡 中: 读者"想知道下一步"
    - 🔴 强: 读者"非得看下一章不可"
  - 本章期望: 反派即将得手，主角生死一线
  - 检查点: 最后一句话是否足够有张力? (应该是悬念而非说明)

- [ ] 是否留有"未闭合的问题"供下章承接？ (避免"完全结束"导致读者没有期待)
  - 检查方式: 本章结尾是否有遗留的悬念、誓言、任务等
  - 特别检查: 不要让反派"成功了"，而是"即将成功"

## 二、约束激活 (Constraint Activation)

**本章主导约束**: 反套路 #3 (反派智商在线) | 镜像对抗深化
**激活强度**: 🔴 强 (本章必须明显体现)

### 2.1 反套路激活
- [ ] 反套路 #3 (反派智商在线) 是否完整激活？
  - 检查清单:
    - [ ] 反派人物首次登场或重要出现
    - [ ] 反派的计划是否"合理且周密"? (不是傻反派)
    - [ ] 反派的能力是否与主角"势均力敌或略胜一筹"?
    - [ ] 反派是否多次"险些成功"? (读者感觉危险)
  - 若失败: 反派仍然脸谱化，需要补充计划、智谋、冷静的表现
  - 关键段落: 反派的出场/对话应该体现"这人很危险"

- [ ] "镜像对抗" 深化是否进行？ (反派与主角的相似性)
  - 检查清单:
    - [ ] 反派与主角是否有"相似的动机或价值观冲突"?
    - [ ] 是否暗示"反派保护主角的真实意图"? (后期伏笔)
  - 本章重点: 反派说出的话是否有"我其实……"的潜台词?

### 2.2 三轴混搭
- [ ] **赛博修真**轴是否体现？ (技术+修真的融合)
  - 检查项: 本章是否涉及黑客、意识空间、程序等科技元素?
  - 预期: 修炼室被"黑客入侵"or 主角进入"虚拟意识空间进行突破"
  - 若没有: 本章显得"传统玄幻"，失去特色

- [ ] **寿命修炼法**轴是否体现？ (突破涉及生命消耗)
  - 检查项: 目标是突破，突破过程是否涉及"献祭"or "寿命消耗"?
  - 预期: 主角献祭记忆或付出生理代价
  - 若没有: 本章的"突破"就是普通升级，威力减半

- [ ] **反派是主角未来身**轴伏笔 (不需要本章揭真相，但需要埋伏笔)
  - 检查项: 反派是否有"时间线謎團"or "类似的决定过程"?
  - 若没有关联: 至少反派的动机应该与"保护"有关，暗示未来身设定

## 三、写作风格 (Writing Style)

**目标风格**: 三九音域 (短句、感官、节奏、去 AI 味)

### 3.1 AI 味检查 ✅ 关键性质检
- [ ] 是否存在"过度解释"? (❌ 禁止: "理性告诉他……"、"他知道……")
  - 搜索关键词: "知道"、"明白"、"意识到"、"理解"
  - 目标: 替换为"行为"和"感官"
  - 例子: ❌ "他意识到不能逃" → ✅ "转身。迎战。"

- [ ] 是否存在"情感命名"? (❌ 禁止: 直接使用"恐惧"、"不安"、"焦虑"等)
  - 搜索关键词: 恐惧、紧张、不安、焦虑、兴奋、期待
  - 目标: 替换为生理反应
  - 例子: ❌ "他感到恐惧" → ✅ "手心全是汗，枪差点拿不稳"

- [ ] 是否存在"工整排比"? (❌ 禁止: 连续 3 句以上结构相同)
  - 检查段落: 如果读起来有"咔咔咔"的机械感，说明排比过多
  - 目标: 打破节奏，混合长短句
  - 例子: ❌ "他站起身。他拍了拍灰。他看向窗外。" 
           → ✅ "起身，拍灰，看向窗外"

- [ ] 是否存在"禁止词汇"? (检查 writing-style-guide.md 的完整列表)
  - 禁止词汇示例: 火山、心湖、涟漪、某种、掀起、不容拒绝……
  - 搜索替换: 逐一删除

### 3.2 节奏感检查
- [ ] 紧张场景是否用"短句主导"? (单句 ≤ 20 字)
  - 检查: 战斗段落的平均句长
  - 若句子过长（如 30+ 字），需要拆分
  - 例子: "轰——！！！ / 惊天动地的爆鸣。/ 细密的丝线被点燃。"

- [ ] 段落长度是否合理? (极少超过 5 行)
  - 检查: 是否存在 7 行以上的大段落
  - 如有: 拆分为多个 3-5 行的小段
  - 特别是对话: 必须独立成段，不能与描写混合

- [ ] 对话标签是否最小化? (避免连续"他说/她说")
  - 搜索: 每页是否出现 > 2 次"他说"/"她说"
  - 替换方案: 用动作、神态、沉默代替

### 3.3 感官具象化检查
- [ ] 是否存在"抽象形容词"? (❌ 禁止: "很恐怖"、"很漂亮"、"很强大")
  - 搜索: "很"、"非常"、"极其"、"相当"
  - 替换: 用具体细节
  - 例子: ❌ "这个地方很恐怖" 
           → ✅ "腐臭味钻进鼻腔，墙壁上暗红色的痕迹还没干透"

## 四、追读力 (Reading Power)

**本章钩子类型**: 危机钩 | **强度标准**: 🔴 强

### 4.1 钩子强度评估
- [ ] 钩子类型是否符合计划? (计划: 危机钩)
  - 检查: 最后 150 字，是否在表现"紧急危险"
  - 若是"悬念钩"或"渴望钩"，说明设定偏离

- [ ] 钩子强度是否达到"强"级别 (🔴)?
  - 强度指标:
    - 🟢 弱 (0-40): 读者感觉"好像还行"，可以中断阅读
    - 🟡 中 (40-70): 读者感觉"想知道下一步"，有继续阅读冲动
    - 🔴 强 (70-100): 读者感觉"必须看下一章"，无法停止
  - 自评: 本章最后一句话，你觉得读者会有什么反应?
  - 调整: 如果是"弱"或"中"，需要加强

- [ ] 钩子的具体形式是什么？ (危险 / 选择 / 未知 / 牺牲)
  - 检查: 最后 200 字，是否清晰表现了某种"急迫感"
  - 例子 (强钩): "反派已经按住了她的喉咙。主角的刀停在半空。'二选一'，反派说。"

### 4.2 微兑现检查
- [ ] 本章是否有"小规模的爽点回收"? (微兑现)
  - 目标: 每 1000 字左右应有 1 次微兑现
  - 检查: 主角是否获得了某个"小胜"(击中敌人、闪过攻击、进度推进等)
  - 若完全没有: 整章憋气，不利于追读

- [ ] 微兑现位置是否合理? (建议 30%、60% 处各一次)
  - 第 30% 处: 小利好，给读者"主角还有机会"的感觉
  - 第 60% 处: 小转折，"局面变了"
  - 最后结尾: 不要兑现，要留悬念

## 五、数据检查 (Data Integrity)

### 5.1 角色一致性
- [ ] 主要角色的言行是否一致？
  - 检查: 本章中主角的性格/能力是否与之前设定符合
  - 若不符: mark 为"人设崩裂"

- [ ] 新出现的角色是否有完整描写？ (名字、身份、外形)
  - 检查: 新角色是否可以直接识别

### 5.2 时间线连贯性
- [ ] 本章的时间设定是否与上章衔接？ (前后关系清晰)
  - 检查: "当晚" / "次日" / 时间词是否足够

### 5.3 力量体系一致性
- [ ] 主角使用的能力是否都在 index.db 中有记录？
  - 新能力: 必须有"学习 / 突破 / 获得"的过程

## 检查流程

### 标准流程 (写作完成后立即执行)

```
1. 本 Agent 根据执行包、约束配置等自动生成清单 (如上)
2. 编写者逐项勾选，标记"✅ 通过" 或 "❌ 需改"
3. 对于"❌ 需改"的项, 在旁边写出具体改动
4. 生成修改建议文档, 按优先级排序
5. 执行修改
6. 重新勾选确认
7. 通过后进入下一环节 (data-agent 处理)
```

### 快速流程 (时间紧张时)

```
只检查"关键项" (标记为 ✅ 的项):
- 开场与承接
- 中段推进
- 结尾钩子
- 约束激活度
- AI 味关键检查
```

若关键项全部通过，可暂时跳过其他项，优先出版。之后在读者反馈后进行微调。
